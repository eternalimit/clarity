## Abstract

This study checks a narrowed hypothesis: could the September 29, October 6, and October 7, 2026 OpenAI announcements be traced specifically to prior published REIK/TCGE mechanisms, rather than resembling common pre-existing approaches? The study retrieves GitHub commits, commit timestamps and source blob identities for four historical REIK/TCGE records, including an actual September 24 research preprint introducing commit, and checks dated first-party OpenAI announcements plus five independent, pre-2026 controls. The outcome is dated evidence for the existence and contents of user-authored artifacts, methodological analogies, and substantial antecedents, but no validated mechanism-specific path of information transfer or adoption. Earliest public availability and absolute original conception are not established by Git commit timestamps.

## Scope, evidence and chain-of-custody distinctions

1. A public GitHub repository as seen *now* is not proof of its visibility at an earlier date, including the date stamped on a Git commit. The repository eternalimit/chatgpt was queried live and was public at inspection time, with repository creation metadata 2025-07-26T18:42:12Z. No historical visibility-change audit, signed independent web snapshot, trusted RFC 3161 token or external archive was acquired.
2. Git commit committer times and author times are preserved metadata but can be authored or altered in Git. Their correspondence to GitHub server receipt time and historical public visibility remains an external validation question.
3. Current GitHub byte reads and Git blob identifiers verify reachable objects; an object appearing in a historical git tree supports archival continuity, but is not by itself independent scientific verification or intellectual-property priority proof.
4. The original source kernel, the full Experiment 029–032 original archives and private material were not acquired in *this* publication-comparison session. An earlier October 9 audit record reports independent original-byte checks and is labeled as **prior reported verification**, not newly reproduced.
5. The source comparison is bounded to the named repos/branches, source files, OpenAI pages, and five control families. Absence of a match within this scope does not establish an absolute negative.

## 4. Mechanism-specific comparison and negative controls

The target is not an exact token/word overlap score: a generic word such as verification is not evidence of lineage. A mechanism is considered distinctive only if an identifiable sequence of constraints and admissible-state transitions is documented in both systems AND there is a separately evidenced transmission path. Using September 24 artifacts as a frozen *inspection baseline* (not prospective preregistration), test five specific correspondences:

| Frozen REIK/TCGE mechanism | Closest OpenAI announcement | Published antecedent / discriminator | Bounded assessment |

| K = R AND I AND independent E; model agreement ≠ independent proof | Oct 6 mathematical disclosure and Lean checking | Mathematical proof check != independent physical-science Echo; W3C PROV and Lean proof practice predate TCGE | Analogous discipline; no exact implementation correspondence shown |
| Explicit U/UNVERIFIED vs FALSE, fail-closed 0 HOLD and DROP U | Sep 29 Dots action approvals; Oct 7 truthfulness discussion | Kleene three-valued logic predates; no public Dots/U mapping or TCGE fail-closed truth table shown | Similar safety intent; no mechanism-level match verified |
| AUTHORIZE ≠ EXECUTE, gated transition and latched state | Sep 29 Dots permissions/auto-review | in-toto requires authorized functionaries and checked steps; auto-review is not an independent scientific witness | Architectural analogy, no demonstrated TCGE adoption |
| Immutable source identity, append-only chronology, honest falsification preservation | Oct 6 research revision and GitHub paper releases | RFC 3161, W3C PROV, in-toto all precede; a commit hash does not prove content truth | Generic-to-moderate governance overlap |
| Iterative/branching transition + unresolved state | Oct 7 native streamed UI and partial responses | UI rendering speed/interaction is not epistemic U or E | Weak conceptual analogy, not a specific structural match |

**Decision rule:** Direct influence REQUIRES a dated independent citation, attributable statement, verifiable inbound reference, distinctive shared implementation artifact, or reproducible information-transmission evidence. In reviewed sources those requirements were **not met**. No claim of confidential internal code inspection or exhaustive negative search is made. The hypothesis remains 0 HOLD, not disproved absolutely.

## 6. Next falsifiable protocol: transfer-channel preregistration with negative controls

**Hypothesis H0 (operational default):** Generic earlier research and independent development are sufficient to explain observed overlap absent a traced transfer.  
**Hypothesis H1 (test target):** The OpenAI implementation or research documentation reflects identifiable, distinctive REIK/TCGE mechanisms through an independently attributable transfer path.

1. Freeze the precisely named September source blobs/commits and exact public-release docs. Record hash, date, source URL, how earliest public visibility was independently validated, or HOLD.
2. Before scoring, define distinctiveness as conjunction of (a) mandatory R AND I AND independently sourced E admission, (b) explicit unverified U not equated to FALSE, (c) deny/hold rather than force success, (d) immutable annotated falsification, and (e) precise causal separation of permission, execution and independent outcome validation. Mere presence of one term scores zero.
3. Acquire published OpenAI technical artifacts that expose actual model policies, agent gate transitions or UI behavior; freeze exact versions and test the conjunction. Do not pretend to have OpenAI private training or code.
4. Compare against controls (Kleene, RFC 3161, W3C PROV, in-toto, OpenAI function calling) plus matched contemporary non-OpenAI agent systems. Blind two external reviewers to document authorship before they classify technical overlap; preserve disagreements.
5. Attempt independent provenance of any supposed transfer (public citation, referrer and dated communication, documented intake or external witness), with attention to whether claimed pathways could predate internal development.
6. Record positive, negative and ambiguous cases without repair; publish the resulting re-runnable evidence manifest.

**Falsifier for a proposed direct-match claim:** A purportedly distinctive match appears unchanged in a dated unrelated predecessor or the allegedly same implementation does not implement the required REIK state/evidence transition.  
**H1 promotion gate:** distinct actual implementation match PLUS independently verifiable transfer pathway PLUS chronology supporting causal possibility. If any term absent → 0 · HOLD.
