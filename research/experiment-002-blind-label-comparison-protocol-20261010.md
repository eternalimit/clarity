## Explicit research hypothesis and feature scope
H0: apparent OpenAI similarities can be explained by earlier widely available ideas, generic engineering analogies, and/or independent development; no traceable transfer established.
H1: there exists BOTH (i) a distinctive shared implementation of the combined TCGE evidence/state sequence, AND (ii) an independently attributable transmission path with feasible chronology.
The criterion for advancing the H1 **influence** claim requires actual architecture-level overlap + independently verified transfer evidence + feasible chronology. A feature score, document similarity, Git commit, or release date alone cannot satisfy it.

Prespecify six binary features based on the **explicit publicly described** content, using 0 for not demonstrated in the examined source; 0 never asserts absence from all undisclosed code:
F1: explicit third verification state that is neither true nor false, distinct from mere incomplete output.
F2: permission/authorization and the execution action separately controlled.
F3: retained, inspectable provenance/evidence chain or versioned research history.
F4: an explicit separately executable verification gate for the specified outcome (independence of organizations is a distinct, stricter requirement).
F5: explicit persistence of valid falsifications/negative evidence rather than overwriting history.
F6: exact knowledge admission by required conjunction of R (reality/direct evidence), I (inference), and independently validated E (Echo), or a proved equivalent typed rule.

Coder MUST cite the supporting exact source path and semantic excerpt, mark ambiguous as 0 pending independent confirmation, and explain analogies rather than invent equivalences.

Broad feature overlap score for a source S: B(S)=sum(F1..F5), maximum 5; specific match flag M(S)=F1&F2&F3&F4&F5&F6, all six required. Do not treat B as probability, statistical significance, or evidence of transfer.

Comparison categories:
- TCGE composite: original September 24 continuity, FIDELITY, GETHUB preprint, Authorize/Gate/Latch (positive specification; heterogeneous documents combined).
- Five historical controls: Kleene 1938 three-valued logic (SEP Spring 2026 frozen edition); RFC 3161 2001 timestamp; W3C PROV Apr 2013; in-toto 2019 software supply-chain; OpenAI June 2023 function calling.
- Five OpenAI dated disclosures: Sep 8 Navier–Stokes; Sep 22 Sol/Luna; Sep 29 dots; Oct 6 mathematics; Oct 7 Intelligent UI.

Blind-label constraint: hide source identity from the *deterministic arithmetic scorer* via row IDs before it calculates scores; the assistant performing manual source-to-feature coding KNOWS identities and IS NOT an independently blinded reviewer. Do not call the result a controlled double-blind experiment, unbiased human review, or independent Echo. A genuine two-person blind code requires independent humans or unrelated models that have not seen the codebook/source key.

Predeclare refusal conditions:
- No original source available => HOLD for that feature.
- Only generic terms (e.g. verify, agent, graph, unknown) => feature not counted absent explicit mechanism.
- No documented transfer pathway => causal influence claim HOLD regardless of B or M.
- A negative-control source implementing an allegedly distinctive isolated feature falsifies that isolated feature's exclusivity.
- Cannot prove historical public accessibility solely from author/committer dates, repository currently public, or a user-uploaded screenshot.
- All matches, nonmatches, and uncertain codings persist.
